# fastscan

A fast, multi-protocol network vulnerability scanner with a built-in web UI.
Detects misconfigurations, default credentials, EOL software, and known CVEs
across 70+ protocol drivers and 245+ detection rules.

---

## Quick start

### Option A: One-command install (Linux, recommended)

Installs all prerequisites, builds both binaries, and starts the UI as a
systemd service that auto-starts on boot.

```bash
git clone https://github.com/navein-kumar/network-scan.git fastscan
cd fastscan/tools/recon/fastscan
sudo ./install-prereqs.sh --start
```

The script prints the URL and generated password when done:

```
  URL  : http://<server-ip>:8888
  user : admin
  pass : <auto-generated>
```

Credentials are saved to `fastscan.env` (never committed).

---

### Option B: Pre-built binaries (Linux amd64)

Download the latest release from the [Releases](https://github.com/navein-kumar/network-scan/releases) page.

```bash
# Extract
tar xzf fastscan-linux-amd64.tar.gz
cd fastscan-linux-amd64

# Install prerequisites (nmap, rustscan, Python3, playwright chromium, etc.)
sudo ./install-prereqs.sh

# Start the UI (runs in foreground)
./fastscan-ui -addr 0.0.0.0:8888 -data ./data -auth admin:changeme

# Or install as a systemd service
cp fastscan.env.example fastscan.env
# edit fastscan.env to set UI_PASS
sudo ./install-prereqs.sh --start
```

---

### Option C: Docker

```bash
git clone https://github.com/navein-kumar/network-scan.git fastscan
cd fastscan/tools/recon/fastscan

# Linux (host network — required for VPN/internal subnet scanning)
docker-compose up -d

# macOS / Windows Docker Desktop (bridge network)
docker-compose -f docker-compose.yml -f docker-compose.bridge.yml up -d
```

Default credentials: `admin` / `changeme`. Set before exposing to a network:

```bash
cp fastscan.env.example .env
# edit .env  ->  UI_PASS=yourpassword
docker-compose up -d
```

## Build from source

Requires Go 1.21+, Node.js 18+, npm.

### Engine only

```bash
go build -buildvcs=false -o ./fastscan .
```

### UI (must build React first, then Go)

The Go UI binary embeds the compiled React frontend via `go:embed`.
The npm build must run before `go build` or the UI will serve a blank page.

```bash
# 1. Build React frontend
cd ui/web
npm ci
npm run build
cd ../..

# 2. Copy built assets into the Go embed directory
rm -rf ui/server/static
cp -r ui/web/dist ui/server/static

# 3. Build the Go UI binary
cd ui/server
go build -buildvcs=false -o ../fastscan-ui .
cd ../..
```

The binary at `ui/fastscan-ui` is self-contained (no external static files needed at runtime).

### Build both with install-prereqs.sh

```bash
# Prerequisites + build engine + build UI
sudo ./install-prereqs.sh --build

# Prerequisites + build + start as systemd service
sudo ./install-prereqs.sh --start
```

## Deploy to a remote server

Use `deploy.sh` to push source, rebuild, and restart from your local machine:

```bash
# Requires SSH alias "uiprod" in ~/.ssh/config pointing to the target server
bash deploy.sh
```

`deploy.sh` does:
1. Pushes source via tar-over-SSH (no rsync needed)
2. Runs `npm ci + npm run build` to compile the React frontend
3. Builds the UI Go binary (with assets embedded)
4. Builds the engine binary
5. Restarts via `systemctl restart fastscan` if the service exists, tmux fallback otherwise
6. Smoke tests the endpoint — verifies JS assets are embedded (fails if blank page)

To target a different server, edit `REMOTE` and `REMOTE_DIR` at the top of `deploy.sh`.

## Prerequisites

`install-prereqs.sh` installs everything automatically on Debian/Ubuntu.
Manual reference:

| Dependency | Required | Purpose |
|---|---|---|
| Go 1.21+ | Build only | Compile engine + UI binary |
| Python 3 + pip | Runtime | XLSX/HTML/evidence export scripts |
| Node.js 18+ + npm | Build only | Compile React frontend |
| nmap | Yes | Service detection, OS fingerprinting |
| rustscan | Recommended | Fast port discovery (falls back to nmap) |
| testssl.sh | Recommended | Deep TLS vulnerability analysis |
| nxc / netexec | Optional | SMB/credential testing helper |
| ike-scan | Optional | IKE/IPsec aggressive mode PSK capture |
| vncsnapshot + imagemagick | Optional | VNC desktop screenshots |
| scrying | Optional | RDP login screen screenshots |

```bash
# Check what is missing without installing anything
sudo ./install-prereqs.sh --check

# Install prerequisites and build engine + UI
sudo ./install-prereqs.sh --build
```

## Running a scan

### Via the web UI

Open `http://<server-ip>:8888`, log in, click **New Scan**, enter a target
(IP, hostname, or CIDR), choose a profile, and click **Start Scan**.

Profiles:

| Profile | Speed | Depth |
|---|---|---|
| fast | ~20s/host | Top ports, basic detection |
| medium | ~60s/host | More ports, credential checks |
| slow | ~3m/host | Full port range, deep TLS |
| crawl | ~10m/host | Exhaustive including UDP |

### Via the engine CLI

```bash
# Single host
./fastscan -target 192.168.1.1 -profile fast

# CIDR range
./fastscan -target 10.0.0.0/24 -profile medium

# Output to directory
./fastscan -target 10.0.0.1 -out ./results/

# Full options
./fastscan -target 10.0.0.1 \
  -profile slow \
  -ports 1-65535 \
  -deep \
  -max-hosts 10
```

### Engine flags

| Flag | Default | Description |
|---|---|---|
| `-target` | | IP, hostname, or CIDR |
| `-target-file` | | File with one target per line |
| `-out` | | Output directory for findings |
| `-profile` | auto | `fast`, `medium`, `slow`, `crawl` |
| `-ports` | built-in | Custom TCP port list |
| `-deep` | false | Enable testssl.sh deep TLS scan |
| `-skip-udp` | false | Skip UDP discovery |
| `-skip-nuclei` | false | Skip Nuclei phase |
| `-max-hosts` | 5 | Concurrent host scan limit |
| `-check-deps` | | Print dependency status and exit |

## Exports

From the UI scan detail page:

| Format | Contents |
|---|---|
| XLSX report | All findings with severity, host, evidence, remediation |
| HTML report | Self-contained report with inline screenshots |
| Evidence bundle | ZIP: per-finding .txt files + terminal-style PNG renders + auto-matched web/RDP/VNC screenshots |

Evidence images: 1600px wide, dynamic height capped at 830px.
Filenames: `<rule_id>_<host>_<port>.png` so screenshots pair automatically with findings.

Screenshots:
- Web: `http_<host>_<port>.png` or `https_<host>_<port>.png` (Chrome-style URL bar injected)
- RDP: `rdp-login_<host>_<port>.png`
- VNC: `vnc-desktop_<host>_<port>.png`

## Detection rules

Rules are plain YAML files in `plugins/`. No rebuild required to add or edit them.

```yaml
id: my-rule-id
title: Short human-readable title
severity: critical|high|medium|low|info
source: ssh
when: version != "" && vlt(version, "8.0.0")
evidence: "{{ .host }}:{{ .port }} running SSH {{ .version }}"
tags: [ssh, outdated]
remediation: |
  Upgrade to the latest stable release.
```

# View live logs

# Stop

cat /opt/fastscan/fastscan.env
